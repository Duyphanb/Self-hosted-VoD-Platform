# ADR-009: Catalog visibility, archive retention, and slugs

Status: Accepted; user approved during Sprint 3 contract preparation on 2026-10-02.

Amended by [ADR-013](ADR-013.md) (2026-11-26, #244) for titles, episodes, franchises and Admin Preview; see the [addendum](#addendum-2026-11-26-content-model-adr-013-planned). Each part takes effect with the ADR-013 slice it names.

Amended by [ADR-015](ADR-015.md) (2026-11-28, #128) for search and discovery; see the [addendum](#addendum-2026-11-28-search-and-discovery-adr-015-planned). Each part takes effect with the ADR-015 slice it names.

## Context

Sprint 3 implements movie CRUD. The frozen contracts left several catalog rules open:

- `SECURITY.md` required a "movie visibility" check for playback and HLS but never defined it. Search, watchlist, rating, and progress had no status rule, so `DRAFT` or `ARCHIVED` movies could leak through later endpoints.
- `BACKLOG.md` required a slug on the admin form, while `UpsertMovieRequest` had none and `movies.slug` is unique and not null.
- Genres were "matched by normalized name" without a definition, while V1 enforces uniqueness only on the raw name and slug.
- `movie_credits` input carried only a name although `people.name` is not unique.
- US-007 requires delete behavior to be explicit before implementation, but the effect of archiving on user-owned records was undefined.

## Decision

Visibility:

- Callers without `ROLE_ADMIN` see only `PUBLISHED` movies. Every endpoint that takes a `movieId` returns the same 404 for a non-published movie as for a missing one. User-facing lists include only `PUBLISHED` movies for every role.
- `ROLE_ADMIN` sees and manages every status on movie detail, update, and archive (`GET`/`PUT`/`DELETE /api/v1/movies/{movieId}`) and under `/api/v1/admin/**`, including `GET /api/v1/admin/movies`. These are the only admin exceptions; admin playback, HLS, progress, rating, and watchlist calls follow the 404 rule. `GET /api/v1/movies` stays published-only for admins too, so its result does not depend on the caller's role.
- The catalog module exposes one visibility check for other modules to reuse.
- A movie may be `PUBLISHED` without a `READY` video asset; clients show that no video is available and hide Watch.
- Addendum (2026-10-29, owner-approved in #100): [ADR-010](ADR-010.md#asset-identity-availability-and-retry-d11-d15-d17) defines a new asset per upload and current as the READY asset with greatest `(created_at, id)`. `videoStatus` is READY while any current asset exists, otherwise the newest asset's status, or null without assets. A failed/pending replacement keeps Watch on the previous current asset. Playback/HLS use only current; non-current HLS returns 404. Archive retains media and related records; superseded media follows ADR-010's manual purge rules.

Archive retention:

- Archive is a status change (`DELETE` or `PUT` with `ARCHIVED`); it is idempotent.
- Watchlist items, watch history, playback progress, and ratings are kept. They are hidden while the movie is not `PUBLISHED` and reappear on restore.

Slugs and matching:

- Slug rule: Unicode NFD, remove combining marks, map đ/Đ to d, lower-case, replace each run of characters other than `a-z0-9` with `-`, trim hyphens.
- Movie slugs are required admin input validated against `^[a-z0-9]+(-[a-z0-9]+)*$`. The backend never generates or rewrites them. A duplicate returns 409 `MOVIE_SLUG_CONFLICT`. Routes use the movie UUID.
- Genre names are trimmed with whitespace collapsed. The genre slug is derived from the name and is the match key, so case, spacing, and diacritic variants map to one genre without a new migration. Renaming a genre recomputes its slug.
- Person names are trimmed with whitespace collapsed before storage. Person slugs are generated by the server with the slug rule, the base truncated to at most 240 characters (base `person` when the rule yields nothing), plus a `-2`, `-3`, ... suffix on collision; a rename excludes the person itself from the collision check.
- Credits identify a person by `personId`. Name-only input is compared case-insensitively, with diacritics significant, against the stored names of all people: no match creates a person, exactly one match reuses it, and two or more return 400 asking for a `personId`. Within one request, name-only entries with equal normalized names resolve to the same person, created at most once.

## Consequences

- No Flyway migration is needed; the committed schema snapshot that CI compares stays unchanged.
- Names that differ only by diacritics (for example `Hài` and `Hai`) are one genre.
- Adding a second person with an existing name requires creating that person first and sending its `personId`.
- Sprints 5-8 must call the catalog visibility check for playback, HLS, progress, rating, watchlist, history, and search, with 404 tests for `DRAFT` and `ARCHIVED` movies.
- The search vector logic must rebuild vectors on genre and person renames and backfill movies created before it exists.
- H2 test schemas come from entities; slug uniqueness, locking, and constraint-to-409 mapping also need PostgreSQL runtime evidence.
- Addendum (2026-10-28, owner-approved in #140): every PostgreSQL cluster (Compose and CI) is initialised with the ICU locale provider and the `vi` locale (`POSTGRES_INITDB_ARGS=--locale-provider=icu --icu-locale=vi`). `sort=title` and genre name ordering therefore follow Vietnamese alphabetical order (for example Ánh Sáng < Avatar < Bắc < Bẫy < Dòng < Đất < Ước < Zootopia) with no query or schema change. H2 compares UTF-16 code units, so ordering is asserted only against PostgreSQL (the Sprint 3 Newman collection). `lower(email)` (ADR-008) behaves the same for email addresses. A cluster created before this change keeps its libc collation until it is recreated; an ICU version change requires `REINDEX`.

## Addendum (2026-11-26): content model (ADR-013, planned)

Owner decisions of 2026-11-25 and 2026-11-26 for #244, specified in [ADR-013](ADR-013.md). Each bullet takes effect with the ADR-013 slice it names; until then the movie rules above apply.

- **Three levels (S2 for titles and episodes, S3 for franchises).** An episode is visible when it and its title are `PUBLISHED`; a title when it is `PUBLISHED`. A franchise's status gates only its own page, its strip of parts, the franchise reference in title responses and its name in search; it never hides its titles. The episode of a `MOVIE` title is always `PUBLISHED` and follows its title, so a film behaves exactly as a movie does today. Every rule above that says "movie" applies to titles, and the 404 rule extends to episode and franchise IDs (`TITLE_NOT_FOUND`, `EPISODE_NOT_FOUND`, `FRANCHISE_NOT_FOUND`). Lists and counts include only visible items, for every role ([ADR-013 D3](ADR-013.md#d3-visibility-at-three-levels)).
- **Admin exceptions (S2, S5).** The catalog writes move under `/api/v1/admin/titles`, so the admin exceptions become exactly `/api/v1/admin/**`, and `GET /api/v1/titles/{titleId}` is published-only for every role. From S5, Admin Preview (owner decision of 2026-11-25) adds `/hls/admin/**`: an admin-only route that plays any READY asset that is not retired, whatever the content status, and writes no viewer progress, history or Continue Watching ([ADR-013 D9](ADR-013.md#d9-admin-preview-and-the-activation-enablement-set-s5)). Admin calls to the viewer playback, HLS, progress, rating and watchlist routes keep the 404 rule.
- **Availability (S2, S5).** "A movie may be `PUBLISHED` without a `READY` video asset" becomes "a visible episode may have no active asset"; clients then hide Watch. The 2026-10-29 addendum's current-asset rule applies per episode until S5; from S5 only the asset the admin activated is playable ([ADR-013 D7](ADR-013.md#d7-activation-s5)).
- **Archive retention** applies at each level. Archiving a title hides its episodes without changing their rows, and restoring it shows exactly its `PUBLISHED` episodes; archiving a franchise hides only the franchise.
- **Slugs.** The slug rule and its 409 apply to title slugs (`TITLE_SLUG_CONFLICT`, S2) and to franchise slugs (`FRANCHISE_SLUG_CONFLICT`, S3). Episodes have no slug. Routes use UUIDs at every level, and titles keep their movie UUIDs.
- **Description.** The title description becomes optional; ADR-014 (planned) defines how it and provider descriptions are displayed (the admin's own text always wins).

## Addendum (2026-11-28): search and discovery (ADR-015, planned)

Owner decisions of 2026-11-03, 2026-11-25 and 2026-11-26 for #128, specified in [ADR-015](ADR-015.md). Each bullet takes effect with the ADR-015 slice it names; until then the rules above and the ADR-013 addendum apply.

- **Eligibility (SR-2, SR-3, RC-1, RC-2).** Search, suggestions, similar titles and the personal Home row list only visible titles, for every role, through the catalog's one visibility check, and their counts exclude hidden titles before paging. A published title with nothing playable stays a search result, labelled by its availability like the catalog list; similar titles and the personal row list only playable titles. A hidden franchise's name never matches ([ADR-015 D1](ADR-015.md#d1-what-search-returns-to-whom)).
- **Search data (SR-1).** The consequence above that "the search vector logic must rebuild vectors on genre and person renames and backfill movies created before it exists" is replaced: SR-1 drops the never-written `search_vector`, and search-owned tables are rebuilt in each catalog write transaction that changes an indexed value, including genre and person renames, and backfilled by a startup reconciler ([ADR-015 D4-D5](ADR-015.md#d4-search-data)).
- **Matching (SR-1).** Search folds accents with its own versioned normalizer ([ADR-015 D2](ADR-015.md#d2-text-normalization-searchtext-version-1)), not with the slug rule above: the slug rule removes every combining mark and would merge が and か.
- **Aliases (SR-1).** Titles gain admin-managed aliases under `/api/v1/admin/titles/{titleId}/aliases`. Alias names are trimmed with white space collapsed, like genre and person names, and are unique within their title, never globally ([ADR-015 D3](ADR-015.md#d3-aliases)).
- **Provider data.** TMDB-origin values and every provider description stay out of the search index; filters (including the catalog list's `genre` and `year`) and similar titles use only values whose origin is not TMDB until ADR-014 (planned) records that TMDB's terms allow each use ([ADR-015 D11](ADR-015.md#d11-provider-data)).
