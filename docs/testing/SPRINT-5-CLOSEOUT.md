# Sprint 5 Worker closeout

Audit date: 2026-11-13. Implementation baseline: `f83f576` on `main`, after [PR #215](https://github.com/Duyphanb/Self-hosted-VoD-Platform/pull/215), plus the job lifecycle logs added by the closeout pull request for [#216](https://github.com/Duyphanb/Self-hosted-VoD-Platform/issues/216).

Sprint 5 Worker has its Definition of Done verified: all eighteen DoD items pass on the merged implementation, within the boundaries stated at the end. Each item maps to the backlog issues below. This is verification evidence, not a replacement for the frozen contracts ([ADR-010](../architecture/adr/ADR-010.md) D6-D10 and D18-D28 and the documents it amends).

Sprint 5 proves that an uploaded video is consumed, probed, encoded to single-quality HLS and stored in the private `vod-hls` bucket, with its asset/job pair reaching READY or FAILED. It does not establish playback through the backend HLS proxy (Sprint 6), production deadline values or A1/VPS capacity.

## Acceptance criteria

Where the evidence runs:
- **W-mvn:** `mvn verify` in the required **Worker Maven build and test** job.
- **W-dep:** `deploy/tests/worker-dependency-smoke.py` in the same job. It runs `WorkerJdbcPostgresTest` and `WorkerObjectStorageSiloTests` against disposable PostgreSQL and the pinned Silo digest.
- **W-ff:** the FFmpeg-tagged tests in the worker image's `ffmpeg-test` stage (`deploy/tests/worker-ffmpeg-tests.sh`), in the same job and in the non-required arm64 workflow.
- **SK-amqp:** `deploy/tests/rabbitmq-publisher-smoke.py` in the required **Skeleton build checks** job, on RabbitMQ 4.4.
- **STACK:** `deploy/tests/worker-stack-smoke.py` in the Skeleton full-stack step. It uploads a generated clip through Nginx to the hardened worker and requires READY HLS.
- **LOCAL:** opt-in suites that no workflow runs, with the local result recorded in their pull requests: `WorkerOrchestrationIntegrationTests` (`deploy/tests/worker-orchestration-smoke.py`, 4/4 on #213) and `EncodingQueueLongHoldBrokerTests` (#208).
